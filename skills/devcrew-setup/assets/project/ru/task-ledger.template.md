# Карточка задачи

Скопируй этот шаблон в карточку конкретной задачи в настроенном каталоге tasks. Заполни поля фактическими данными; пустые списки означают отсутствие записей, а не успешную проверку. Обновляй состояние после значимого этапа и перед передачей работы. Не перезаписывай чужие записи и согласованные требования.

```yaml
task: null
status: planned
updated_at: null
workspace: null
branch: null
git_head: null
state:
  done: []
  in_progress: []
  next: null
  key_files: []
blockers: []
evidence: []
```

`status`: planned / in_progress / blocked / review / done. `updated_at` — время с часовым поясом; `workspace` — абсолютный рабочий каталог. `branch` и `git_head` допускают null, если Git недоступен. `done` перечисляет завершённые этапы с результатами; `in_progress` — незавершённую работу; `next` — одно конкретное следующее действие; `key_files` — пути с назначением. Блокер содержит причину, что блокирует и от кого требуется действие. В `evidence` сохраняй пути к записям CLI и отчётам, проверенное состояние и охват. Статус done сам по себе не доказывает приёмку.

## Цель и границы

Запиши ожидаемый результат, входящие и исключённые изменения, зависимости. Сошлись на постановку и источники решений; не дублируй весь пакет.

## Критерии приёмки

Для каждого критерия запиши наблюдаемую проверку и ссылку на её результат. Отдельно укажи непроверенное и причину.

## Владение и этапы

Укажи исполнителя, каталог, границы файлов и зависимости каждой части. Незавершённая часть блокирует зависимую волну; записи проверок волны относятся к объединённому дереву.

## Решения и отклонения

Фиксируй существенные решения, их источники, изменения scope и причины пропуска применимых проверок.

## Продолжение

Прочитай `state`, блокеры и связанные файлы. Сверь каталог, ветку, HEAD, локальный diff и свежесть нужных записей. Если код изменился, сохрани прежние результаты как историю, отметь затронутые проверки как устаревшие и обнови `next`. Не восстанавливай статус по памяти разговора и не пересоздавай всю карточку.
