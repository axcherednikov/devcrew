# Task retro

After a task closes, consider retro only when it was significant (completed epic/large multi-step task, meaningful implementation → verification → review cycle, multiple fix/review loops, or a substantial session with repeatable lessons). Skip trivial fixes, renames, small local work, and incomplete work without sufficient evidence. It is optional and must not delay closure. Follow [session harvest](session-harvest.md) for bounded evidence, recurring-problem/loop analysis, memory deduplication, trigger → action lessons, Minimal Diff marker classifications, and reporting. Keep one-off findings in the configured task card; persist only nonduplicate, reusable project/role lessons in configured memory. Do not edit installed skills, package templates, global memory, external trackers, or global policy as a side effect. Record `POLICY_CANDIDATE` recommendations separately for an explicitly scoped policy task.
