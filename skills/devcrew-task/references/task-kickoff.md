# Task kickoff

1. Read applicable `AGENTS.md`, `.codex/devcrew.json` when present, the configured project context, the task card, and the current Git state.
2. If the request is raw or ambiguous, use `$devcrew-brief`; record open product questions before implementation.
3. DIRECT: inspect the known bounded target and its check. AGENT EXECUTION: inspect only routing context and any candidate plan; assigned research/planning roles own substantive code/flow investigation. Keep accepted scope and exact file ownership in the task brief.
4. Classify DIRECT versus AGENT EXECUTION using every condition in [implementation strategy](implementation-strategy.md). For AGENT EXECUTION, check runtime/role availability and validate an existing plan or dispatch bounded research and decision/planning before executor implementation. Reclassify explicitly when scope or behavior changes.
5. DIRECT may be implemented by the host. In AGENT EXECUTION, executor-agent owns production implementation; the host coordinates and does not duplicate work. Keep one writer per checkout. Do not introduce parallel writer waves through this task policy.
6. Run deterministic checks and inspect semantic output. Every AGENT EXECUTION implementation then receives independent read-only review in a separate reviewer-agent context. DIRECT uses inline diff inspection; no separate reviewer is required. Existing wave evidence gates apply only if another explicitly authorized workflow already uses waves.
7. At significant stage boundaries and before handoff, update the structured card according to [session snapshot](session-snapshot.md): completed and current work, next action, key files, blockers and evidence. Preserve project conventions. Finish document edits before final state capture/checks; machine reports belong in the configured checks directory. Persist durable lessons in the configured memory location only when they generalize.

The parent session owns final scope decisions and external publication. A failed evidence or review gate stops completion.
