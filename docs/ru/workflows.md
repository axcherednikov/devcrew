## Опишите результат, который можно проверить

В чате целевого проекта вызовите `$devcrew` и опишите, что должно измениться. Например: «Исправь экспорт CSV. Для пустой выборки файл должен содержать строку заголовка. Запусти тесты экспорта». Укажите ветку, файл, задачу или PR, если от этого зависит предмет работы. Для чтения задачи из трекера понадобится подключение с доступом к ней.

| Что нужно сделать | Skill |
|---|---|
| Подготовить репозиторий или разобраться в существующем продукте | `$devcrew-setup`, `$devcrew-product-onboard` |
| Согласовать постановку, реализовать задачу или выполнить этап готового графа задач | `$devcrew-brief`, `$devcrew-task`, `$devcrew-autopilot` |
| Найти причину ошибки или оценить устройство существующей системы | `$devcrew-diagnose`, `$devcrew-architecture` |
| Проверить изменения или протестировать работающий локальный сервис | `$devcrew-review`, `$devcrew-qa` |
| Координировать задачи, сохранить ход сессии или передать результаты другой команде | `$devcrew-coordinate`, `$devcrew-session`, `$devcrew-handoff` |
| Составить сообщение коммита, проверить skills или запросить краткие ответы | `$devcrew-commit-message`, `$devcrew-skill-doctor`, `$devcrew-small-talk` |

## Реализация

Локальную правку с ясным контрактом и детерминированной проверкой агент может выполнить напрямую. Для рискованных или неопределённых изменений DevCrew разделяет реализацию и ревью. Агент проверяет текущую ветку, сохраняет локальные изменения и следует правилам проверок целевого проекта. Явно укажите, если требуется коммит, слияние, push или отдельный worktree. При запуске autopilot для готового графа задач действует собственная процедура коммита каждой принятой задачи. Проверьте выбранную фазу до запуска.

Для формальной фазовой задачи `phase source-bind` привязывает проверенный файл или вложение. Для запроса из чата можно использовать структурированный Intent Contract. До подтверждения хеша сверьте цель, требования, критерии приёмки и границы задачи. При инициализации фазы schema v2 координатор передаёт `--intent-assessment`. Один хеш сообщения не позволяет восстановить исходный запрос. В конце отдельный ревьюер сверяет результат с привязанным источником. Команда `phase resume` возвращает `TASK_DONE` после проверки всех обязательных свидетельств. [Контракт runtime](../runtime-contract.md#original-intent-and-task-completion)

## Ревью и проверка результата

Укажите объект ревью: «Проверь изменения в индексе» или «Проверь этот PR относительно его базовой ветки». В замечании должны быть файл, достижимый сценарий и последствие. Комментарии во внешнем сервисе публикуются по явному запросу. Для QA укажите локальный тестовый сервис и конкретный сценарий пользователя. Используйте синтетические данные. Для проверки через браузер нужна поддержка хоста. Запрос существующего QA-отчёта читает сохранённые материалы.

Сохранённую запись команды можно проверить через `verify-check --record PATH`. Из журнала видно, что именно запускалось. Модульные тесты, оценка маршрутизации моделью и живая сессия Codex проверяют разные свойства системы. [Команды и форматы](../runtime-contract.md) · [Сценарии маршрутизации](../../tests/routing-evals.md)

## Передача постановки в отдельный чат

Если хост поддерживает видимые чаты проекта, родительский чат может передать утверждённую постановку в дочерний и следить за результатом. Для проверки откройте новую сессию проекта. После явного одобрения должен появиться один дочерний чат. Без одобрения проверьте, что чат и сообщение не создаются. Если передача прервалась, при возобновлении сверьте существующий чат и последнее действие до повтора отправки. Так одна постановка не превратится в две задачи. [Устройство передачи](../brief-supervision-adr.md)

## Где искать результаты

Соглашения проекта и долговечные знания хранятся в настроенных каталогах контекста и памяти. Рабочие записи задач по умолчанию находятся в `.codex/tasks/`, состояние сессий — в `.codex/sessions/`, журналы проверок — в `.codex/checks/`. Пути можно переопределить. Перед переносом файлов проверьте `.codex/devcrew.json`. [Структура каталогов](project-state-layout.md) · [Хранение SSH-профилей](../server-profiles.md)
