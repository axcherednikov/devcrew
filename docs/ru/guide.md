# Установка и проверка DevCrew

[English](../en/guide.md) · [Рабочие процессы](workflows.md)

## Окружение

Установите Git и Python 3.11+ на Linux, macOS, Windows 10+ или Windows Server 2016+. CLI использует стандартную библиотеку Python. В нативной Windows хукам нужны лаунчер Python (`py -3` в PATH) и клиент Codex с поддержкой команд хуков для Windows. Используйте локальный каталог NTFS и приватный каталог данных плагина. Для управления процессами используются Job Objects. Проверить поддержку маркетплейса можно командой `codex plugin --help`.

Для работы в чате нужен клиент Codex с поддержкой skills. Для делегирования клиент должен уметь запускать отдельных агентов с моделями и уровнями рассуждения из [правил выбора моделей](../cost-policy.md). Для обычной реализации нужна модель с возможностью `bounded` и уровнем рассуждений `medium`, для независимого ревью — с возможностью `strong` и уровнем `medium`. Идентификаторы и приоритеты подходящих моделей предоставляет хост. Если локальная роль закреплена за другой конфигурацией, хост должен уметь запустить отдельного агента с нужными параметрами и теми же инструкциями. Для построчных комментариев авторизуйтесь на нужном сервере через `gh` для GitHub или `glab` для GitLab. Для браузерной QA браузер хоста должен иметь доступ к локальному тестовому сервису.

## Установка плагина

1. Скачайте и распакуйте архив исходников. Если у вас уже есть Git-клон, выгрузите файлы коммита в новый соседний каталог. Выполните команды из корня клона и выберите свободное имя каталога.

   ```sh
   release_dir="../devcrew-release"
   mkdir "$release_dir" && git archive HEAD | tar -x -C "$release_dir"
   cd "$release_dir"
   ```

   Откройте терминал в распакованном корне, где находится `.codex-plugin/plugin.json`. При локальной установке Codex копирует содержимое каталога. Поэтому в marketplace должны лежать только файлы релиза. В рабочем клоне могут также находиться история Git, игнорируемые файлы и состояние локальных запусков.
2. Зарегистрируйте каталог как локальный marketplace и установите плагин:

   ```sh
   codex plugin marketplace add "$PWD"
   codex plugin add devcrew@devcrew-community
   ```

3. Откройте в Codex **проект, в котором предстоит работать**. Попросите `$devcrew-setup` подготовить его. Setup читает соглашения проекта, устанавливает 12 ролей в `.codex/agents/` и настраивает пути для контекста, памяти и проверок. Существующие документы сохраняются. При конфликте определений ролей setup покажет проблемные файлы.
4. Прочитайте определения хуков перед подтверждением доверия. Откройте новую сессию проекта. Сделайте небольшое изменение и попросите `$devcrew-review Проверь мои незастейдженные изменения`.

Сохраняйте каталог релиза, пока его marketplace зарегистрирован. Для перехода на другой релиз удалите плагин и marketplace, затем повторите установку из нового распакованного каталога и откройте новую сессию. Для удаления выполните `codex plugin remove devcrew@devcrew-community`, затем `codex plugin marketplace remove devcrew-community`. Документы, роли и журналы целевого проекта хранятся отдельно от установленного плагина.

## Проверка CLI во временном проекте

Запустите команды из каталога исходников плагина. Они создадут временный Git-репозиторий, подготовят проектные файлы, запишут результат одной команды и проверят его:

```sh
demo=$(mktemp -d)
git init -q "$demo"
python3 -B scripts/devcrew.py init --project "$demo" --language ru
python3 -B scripts/devcrew.py doctor --project "$demo"
output=$(python3 -B scripts/devcrew.py run-check --project "$demo" --name smoke -- python3 -c 'print("smoke ok")')
record=$(printf '%s\n' "$output" | head -n 1)
python3 -B scripts/devcrew.py verify-check --record "$record"
```

В последнем ответе ожидается `"status": "verified"`. Запись и журнал лежат в `.codex/checks/` временного проекта. У нового Git-репозитория ещё нет первого коммита, поэтому в результате возможно предупреждение об отсутствии HEAD.

### Нативная Windows (PowerShell)

Для установки из клона в PowerShell выполните `git archive --format=zip -o ../devcrew-release.zip HEAD` и распакуйте архив в новый каталог командой `Expand-Archive ../devcrew-release.zip ../devcrew-release`. Перейдите в распакованный каталог и выполните команды регистрации маркетплейса из раздела установки.

Из каталога распакованного плагина выполните проверку в новом локальном каталоге:

```powershell
$demo = Join-Path ([System.IO.Path]::GetTempPath()) ([guid]::NewGuid().ToString())
git init -q $demo
py -3 -B scripts/devcrew.py init --project $demo --language ru
py -3 -B scripts/devcrew.py doctor --project $demo
$python = py -3 -c "import sys; print(sys.executable)"
$result = py -3 -B scripts/devcrew.py run-check --project $demo --name smoke -- $python --version
py -3 -B scripts/devcrew.py verify-check --record $result[0]
```

## Язык общения и документов

Инструкции плагина и роли агентов написаны на английском. Если вы пишете по-русски, DevCrew отвечает по-русски. Язык документа можно задать отдельно, например обсудить задачу по-русски и попросить постановку на английском. Имена команд, идентификаторы кода и машинные поля сохраняются без перевода.

При запуске из терминала новые проектные документы по умолчанию создаются на английском. Для русских документов используйте `init --project PATH --language ru`, для английских — `--language en`. Повторный запуск сохраняет существующие документы. Доступны [русская постановка](../../skills/devcrew-brief/references/ru/template-main.md), [английская постановка](../../skills/devcrew-brief/references/template-main.md), а также соответствующие планы, краткие постановки, отчёты и шаблоны передачи результата.

## Данные и хуки

- Контекст и долговечная память хранятся в проекте как обычные документы. Карточки задач, роли и логи по умолчанию лежат в игнорируемом каталоге `.codex/`. Перед публикацией проектной документации проверьте подготовленный diff.
- После подтверждения доверия хук обучения обрабатывает каждое отправленное сообщение в инициализированном проекте. Локально сохраняются SHA-256, идентификаторы сессии и хода, путь проекта, время и явное подтверждение условий задачи, если оно было. Запись действительна 24 часа, очистка происходит при обращении. От старых установок могли остаться файлы с полными текстами сообщений. [Восстановление и хранение данных](../bootstrap-recovery.md)
- Чтобы отключить хук обучения для одного проекта, запишите `{"enabled":false}` в `.codex/devcrew-learning.json`. При этом перестанут создаваться новые подтверждения условий задачи через хук. Хук уведомления о синхронизации работает отдельно.
- В журнал проверки входят аргументы команды и объединённый вывод. Не передавайте секреты в аргументах и не выводите их в лог. Успех проверки подтверждает выполнение записанной команды. Соответствие этой команды задаче оценивает ревьюер.

## Если что-то пошло не так

| Симптом | Что проверить |
|---|---|
| Codex не находит плагин | Зарегистрируйте абсолютный путь к корню релиза и используйте точное имя `devcrew@devcrew-community`. |
| После setup нет ролей | Откройте новую сессию проекта. Из исходников выполните `python3 -B scripts/devcrew.py doctor --project /path/to/project`. Команда проверяет файлы. Доступность ролей в текущей сессии показывает хост. |
| `AGENT_RUNTIME_REQUIRED` | Сверьте доступные модели, уровни рассуждения и возможность запуска отдельного агента. |
| В терминале нет `PLUGIN_DATA` | Codex передаёт каталог доверенному хуку. Проверяйте хук в Codex. Пример с временным CLI-проектом запускается и из обычного терминала. |
| Хук заблокировал обычное сообщение | Посмотрите причину ошибки, проверьте реестр требований и лимит события в 1 МиБ. На время диагностики можно отключить хук обучения для проекта. |
