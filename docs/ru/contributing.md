# Участие в разработке

[English](../../CONTRIBUTING.md)

В сообщении об ошибке приведите минимальный пример, версии DevCrew, Python и Codex, операционную систему, ожидаемый результат и фактический вывод. Замените имена внутренних репозиториев, пути пользователей, токены и клиентские данные синтетическими примерами. Для уязвимостей используйте [приватный канал](../../SECURITY.md).

1. Прочитайте [соглашения репозитория](../../AGENTS.md). Инструкции процессов лежат в `skills/`, реализация CLI — в `scripts/`, обработчики событий — в `hooks/`.
2. Работайте в отдельной ветке. При изменении поведения добавьте регрессионный тест для соответствующей команды или процесса. Обновите пользовательскую документацию на обоих языках.
3. Из корня репозитория запустите подходящие проверки. Для этого нужны Python 3.11+ и Git:

   ```sh
   make check-package
   make test-serial TESTS='test_devcrew.DevCrewCLITest'
   ```

   Выберите тестовый модуль или класс по изменению. Полный набор запускается через `make test`. Изменения маршрутизации и моделей дополнительно проверяют по [сценариям оценки](../../tests/routing-evals.md). Для чистого клона предусмотрен [пример запуска CLI](guide.md).
4. Пишите тему коммита по-английски в повелительном наклонении, например `fix(cli): preserve the exit code`. В PR опишите изменение для пользователя, выполненные проверки и то, что осталось проверить на живом хосте.

После изменений в исходниках переустановите плагин и откройте новую сессию Codex.
